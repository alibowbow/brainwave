# One old-context drain discrimination — version 2

This is a diagnostic intervention, not an unchanged original-gate pass. It runs the exact original winter verification sequence with one inserted call **after all three rapid remounts and immediately before the original final unmount**. This position includes those remounts' static redraws in the old-context work being tested.

```sh
SCENE_BROWSER_PATH=/path/to/chromium COZY_OUTPUT=components/immersiveWorlds/cozyRooms/qa/gl-boundary/evidence/covered-drain node components/immersiveWorlds/cozyRooms/qa/gl-boundary/run.mjs
```

The runner records source, bundle, original test-body, intervened test-body, generated runner, dependency and instrumentation hashes. `COZY_BUILD_ONLY=1` validates the build and provenance without opening a browser. Run one browser workload at a time. There is no retry loop.

The insertion requires the existing engine to be paused, yields 180 ms, inserts `fenceSync(SYNC_GPU_COMMANDS_COMPLETE, 0)` into that canvas's existing context, and flushes. It observes `clientWaitSync(sync, 0, 0)` after 16 ms event-loop yields. There is one **120,000 ms absolute browser deadline**, with a **125,000 ms external Node ceiling**. This declared extra wait is separate from the unchanged subsequent 120-second fresh-ready gate.

A delayed host resize can submit a paused static redraw after fence placement. Version 2 delegates `CozyEngine.renderFrame` unchanged and records the before/after frame, time, running and renderer entry/return/throw counters for each successful exact `renderFrame(0)` call. A pending fence may be replaced only when a contiguous chain of those explicit successful calls explains every counter increment: each call must remain paused, advance one frame and exactly one renderer entry/return, preserve time, and add no renderer throw. Unchanged time alone is insufficient. The superseded sync is deleted once, then a new fence covers the latest actual submission. The original deadline never restarts; at most **eight replacements after the initial fence** are allowed. Every fence retains its placement counters, matched call IDs, status history, poll counts, timings, deletion and replacement reason. No scene work is added.

Canvas/engine/context identity, connection, size, backing-write count, scene time, running state and input diagnostics must remain unchanged. Null fences, `WAIT_FAILED`, context loss, unaccounted increments, those invariant changes, an unknown status, the replacement cap or deadline expiry end the comparison before final disposal/recreation. Every non-null owned sync must receive exactly one successful `deleteSync`, including superseded syncs and the final sync in `finally`. If the page is blocked, the external deadline cannot force in-page cleanup to execute; the recorded last phase and incomplete reconciliation remain evidence, not completion.

Repeated `TIMEOUT_EXPIRED` observations are counted rather than individually streamed. Status transitions and roughly one-second progress are retained, together with fence creation, flush, wait-call and deletion durations. There is no `finish()`, synchronous busy wait, positive-timeout GL wait, readback, quality change, forced context loss, or extra scene render. A signaled fence means preceding commands on that old GL context completed; it does not establish presentation or physical memory reclamation.

The new browser entry layers on the existing recreation diagnostic. It observes renderer entries/returns, cumulative draw/triangle/point/line counters, last submission times, context identities, lifecycle phases, native backing setter calls and host-caught error reasons. Old renderer entries invalidate the pending fence until the successful-zero-dt chain is verified and a covering replacement is placed. Backing assignments remain terminal. Once the latest fence signals, any later old-engine renderer entry invalidates the comparison, without suppressing the production operation or re-arming again. Monitoring continues through release, the five-second grace, disposal and the final fresh-ready summary. Counter snapshots at the latest signaled fence, disposal entry/return and final summary must agree. The preexisting host, engine and renderer behavior is delegated unchanged. Resource-deletion commands issued by the later disposal are outside the earlier fence; the drain does not prove those cleanup commands have completed.

Only four additional GL methods are wrapped: `compileShader`, `linkProgram`, `getShaderParameter` and `getProgramParameter`. Original arguments, returns, exceptions and extensions are preserved. No shader strings are logged. Entry/return detail is capped at 64 calls per method per context; aggregate counts/durations and the current call remain in the final summary. Other GL functions and browser/driver internals are untraced. A long first-render interval outside recorded compile/status calls must remain an untraced boundary, not an invented cause. These observers add timing overhead.

`phases.jsonl` streams scalar events through console and binding delivery. Before browser cleanup, the runner retrieves the complete in-page scalar-event array, appends recovered records, flushes the stream, and reads the persisted file back. It compares identity/content and sequence completeness through each in-page document watermark, saves those exact read-back bytes as `phases-readback.jsonl` with their hash, and writes `reconciled-events.json` plus `reconciliation.json`. Later heartbeats are outside the watermark claim. A blocked page gets a bounded one-second failure observation; retrieval failure, disk mismatch, duplicate or unresolved gap makes the diagnostic incomplete. Success uses a three-second reconciliation bound. The first captured failure is saved before this observation. Source and bundle hashes are checked again before cleanup. The final report is deliberately named `diagnostic-sequence.json` and sets `originalGateClaim: false`.

Use the recorded first/second context, host state, React DOM, exact phase boundaries and reconciliation coverage to interpret the result. This experiment does not by itself establish hardware performance, a renderer submission bound, or the cause of historical timeouts.

The first guard-invalidated attempt and its version-1 source snapshot remain unchanged under `evidence/drain/`. Version 2 defaults to the separate `evidence/covered-drain/` output. A successful version-2 result means the latest fence signaled covering the latest observed completed submissions, subject to the post-signal coverage check; it is not a retry of a fresh-context ready timeout.

## Undrained control

`COZY_GL_MODE=undrained` selects the single undrained control and defaults to `evidence/undrained-control/`. It executes the entire original assertion sequence byte-for-byte, without the drain insertion or any added pre-disposal wait. It builds the same unchanged browser entry and asserts that production-source, browser-bundle and entry hashes exactly match the completed covered-drain manifest before opening a browser. Mode and original/executed sequence hashes are saved in provenance. The normal default remains `covered-drain`.

```sh
COZY_GL_MODE=undrained SCENE_BROWSER_PATH=/path/to/chromium node components/immersiveWorlds/cozyRooms/qa/gl-boundary/run.mjs
```

Control success still requires the original sequence assertions, complete disk reconciliation, unchanged source/bundle identity and browser cleanup. It has no drain/coverage requirement because no drain runs. Both modes remain `diagnosticOnly: true` and `originalGateClaim: false`: the control retains the same QA observers, including coarse GL boundary timing. Existing covered and invalidated-run artifacts are not rewritten.
